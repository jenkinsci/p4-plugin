Allows jobs to add the P4: Attempt an AI fix when the build fails build step. While this is unticked the step is not offered at all, and any job already configured with it does nothing.

This is an administrator-level switch because the feature has two effects that individual job owners should not be able to turn on unilaterally:

  • It sends build output — a log excerpt, failing test names and assertion messages, and the source files involved — to whichever AI provider the job is configured to use. Recognised secrets are masked first, but treat this as sending build content off-site.
  • It costs money per failed build, and a job that fails repeatedly will spend repeatedly. Each job can set its own token ceiling.

Enabling this switch does not make anything happen on its own. A job must also add the build step, and that step defaults to a dry run: it verifies a fix and prints it, without changing anything in the depot.
